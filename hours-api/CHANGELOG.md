# @operai/hours-api

## 0.2.1

### Patch Changes

- 8653331: The local-setup test now reads the example file together with the committed direnv file (which supplies `DATABASE_URL`), so it follows the setup the service actually has. No change to the service.
- 8653331: Inner deadlines now fit inside their callers' (specs/20261126-teams R13). The host routes of projects-api and crm-api (`/activity-host/v1/resolve`, `/meeting-host/v1/resolve`) wait at most 500 ms for a permission check they have not cached, then answer the usual 503 `authz_unavailable`; the check is single flight per person, is not aborted, and fills its 30 s cache for the retry. hours-api waits 6 s, not 2 s, for activities-api's lists and the meetings list, which ask a host themselves; activities-api waits at most 800 ms for the names on a list, and meetings-api's list makes no permission call (it never read the answer) and waits at most 800 ms for its creators' names. A name not known in time reads as unknown and is known on the next load. No wire contract changes.
- 8653331: A U+0000 in any input is a 400, never a 500. Postgres text (and the text inside jsonb) cannot hold it; every backend's global error handler now answers the database's refusal (Postgres 22021 / 22P05, Prisma P2039 / P2010) with a 400 `validation_failed` (hours-api: `invalid_request`) that names no value and none of the database's words, so a route nobody remembered is still not a 500. In auth a guard in front of the whole app refuses a NUL in the path, the query or a JSON body before any route runs (`GET /admin/users?q=%00`, `POST /admin/departments`, roles, invitations, legal entities, …). In projects-api the shared text helpers (`requiredText`, `optionalText`, a new `searchText`) refuse it, which covers `GET /projects?q=`, a project's name, a T&M position's profile, the Bexio order id and `GET /system/purchase-orders?dealIds=`.
- 8653331: The safety net that answers 400 when Postgres refuses a U+0000 now leaves one log line, `[nul] database refused U+0000 or invalid text` and the Prisma and SQLSTATE codes (`P2039/22021`), so a value built by the server with bad bytes is no longer blamed on the client without a trace (security review A09). The line carries only codes taken from the two closed sets the detector already knows: no message, value, argument, request or person. No wire contract changes.
- 3e5d1b5: A project the host answers with `assignees: null` (an attached team's members could not be read) refuses a booking as 503 `host_unavailable` instead of reading as a malformed answer; the project's label still resolves.

## 0.2.0

### Minor Changes

- 2b3d2fe: Add hours-api (specs/20261112-time-tracking, ADR 20261112-hours-api-time-entries-own-service-hours-catalog, 20261112-time-bookability-asked-of-owners-meeting-hosts-system-route), the service behind time tracking: the hours people spend on company work. A time entry is one person's own declaration of a duration, on one day, on a project, a deal, a meeting or other work. It is a whole number of 30-minute steps, never a time of day, and only its author can change or delete it. Whether a person may book on a project, a deal or a meeting is asked of the service that owns it (`projects-api`, `crm-api`, `activities-api`, `meetings-api`) as that person on every write, and a write fails closed when the owner cannot answer. Holders of the new `time-entry:read-all` permission can list and total everyone's hours; holders of `time-list:manage` keep the categories and the work types people pick from (retire and restore, never delete). Totals group by person, project, deal, category, month or day, and merge what the viewer may not read into one group.
  - **Operators:** a new database `hours`, a Railway service and the env contract in `tools/env-doctor`. hours-api reads a meeting's current deal from `meetings-api` with its own service credential, so it needs `SERVICE_CLIENT_ID`, `SERVICE_CLIENT_SECRET` and `SERVICE_AUDIENCE` to start; `auth` needs the `hours-api` client (scope `meetings.hosts.read`, added to `SERVICE_CLIENTS` only after the new `auth` is live, because an unknown scope stops it) and `meetings-api` needs `SERVICE_AUDIENCE`. Until those last two exist a meeting's deal reads as unavailable; nothing else is affected.

### Patch Changes

- 2b3d2fe: hours-api takes the dependency versions every backend moved to: zod 4.6.7 and `@hono/zod-openapi` 1.6.3 (GHSA-mrhx-c7xc-m3w5), `@scalar/hono-api-reference` 0.12.17 and hono 4.13.16 with `@hono/node-server` pinned to 2.1.6. A request body sent with a Content-Type other than JSON now answers a 415 Problem (`Unsupported Media Type`) instead of 400 `invalid_request`; malformed JSON and a missing body are still 400 `invalid_request`, and zod's own wording of some messages changes.
