## Findings

### 1. The `estimai-api ↔ auth` identity seam is never verified end-to-end (ac_satisfaction, test_quality)
Each half is well tested in isolation — `auth/src/auth/identities.routes.test.ts:97-130` resolves real active/deleted/unknown users over real HTTP, and `estimai-api/src/lib/authClient.test.ts:108-397` covers the client (cache, 60s TTL, 100-id chunking, per-batch degradation) against mocked `fetch`. Nothing joins them:
- `estimai-api/src/estimates/estimates.routes.test.ts:2664` and `:2705` assert `owner?.status === "unknown"` — the *degraded* outcome is the expected value. These assertions pass only because the integration run's real `auth` returns 401 (I observed `[authClient] … responded with HTTP 401` in the `bun test` output). A working `auth` would fail them.
- `orphaned-estimate.test.ts` never asserts `owner:{status:"deleted", name:null}`, so plan.md's AC-10.5 api-level row is unimplemented.
- `shell/e2e/estimate-sharing.spec.ts:182-187` asserts the shared row's badge but never the owner's name, and because identity resolution **fails soft by design** (ADR-0039), a wholly broken identities contract renders "Unknown wellD member" and the e2e still passes green.
Net: `POST /authz/users/identities` + its client + its cache — an entire endpoint and ADR — have no test at any level proving a non-`"unknown"` identity reaches the wire. Fail-soft is correct; fail-soft *plus* an unasserted seam means the failure is silent. This is the same seam class that produced the two CORS defects and the If-Match defect. To lift AC satisfaction to 5: one `estimai-api` integration case with a mocked `resolveIdentities` returning `active`/`deleted` asserting the wire body, and one e2e assertion on the rendered owner name.

### 2. Test shallowness shipped a feature-breaking defect (test_quality)
`3b68b58` fixed `estimatesApi.update()` sending `If-Match: 7` where the server's `parseIfMatch` is `/^"(\d+)"$/` (`estimates.routes.ts:192-198`) — **every save 428'd**. T15's done-when said "unit tests prove `update()` sends the `If-Match` header", and the test did exactly that: asserted presence, not value. Both sides of one wire contract were tested independently and never against each other. Now covered non-vacuously (`estimatesApi.test.ts:324-345`, with a second case proving the header isn't hardcoded), but the binding remains a code comment rather than a shared fixture. The two CORS defects (`0cdc4db`) were structurally invisible to transport-mocked suites and are now closed properly by `cors.preflight.test.ts` mounting the real middleware — that remediation is exemplary; the If-Match one was catchable and simply wasn't asserted.

### 3. AC-1.2's timing property: an honest reading, not a quiet weakening (no deduction)
Judged deliberately and adversarially. The plan's "quantised to a fixed floor over an equalised work path" is a legitimate realisation, not a dodge, because the primary control is *not* the floor: `auth` collapses both negative causes into the same `{eligible:false}` body **at the source** (`appAccessCheck.routes.ts:262-302`), so the property survives a caller who bypasses `estimai-api` entirely. The equalisation is real (`$queryRaw` folding no-such-user and soft-deleted into one zero-row result; `resolveEffectivePermissions` executed against a sentinel on the miss path so both branches pay one probe + one resolver call). It is genuinely tested, not asserted: 50 samples per cause, medians ≥ floor and delta < 10% of floor (`appAccessCheck.routes.test.ts:272-341`), plus a one-key snapshot (`:158-167`) that breaks on any future field addition. Residual I can still see, bounded and worth recording: the floor is computed from handler entry, so if either negative path ever exceeds `APP_ACCESS_CHECK_FLOOR_MS` (150ms) under load the masking stops — the plan attributes the residual to "clock jitter" but not to DB latency crossing the floor.

### 4. The supersession is justified but not back-linked (spec_fidelity)
ADR-0038 is a careful document — it states the amendment, scopes it (ADR-0004's JSONB shape, size guard and deep-equal fidelity untouched), and records why `updatedAt`-as-precondition and content-hash ETags were rejected. `spec.md:14-28` scopes it from the 013 side, CLAUDE.md indexes it. But the *superseded* artifacts carry no pointer: `docs/adr/0004-…` still reads `**Status:** Accepted` with no `**Amended by:**` line, despite `docs/adr/0021-…:8` establishing exactly that convention in this repo; and `specs/001-estimate-persistence/spec.md:129` / `plan.md:203` / `design.md:390` still assert last-write-wins. A reader arriving at ADR-0004 or spec 001 today learns nothing about the reversal. Same pattern for ADR-0005 ← ADR-0037, though 0005 already carried an un-back-linked exception (ADR-0026), so 0037 follows the weaker precedent.
